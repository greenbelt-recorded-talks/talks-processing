Move the Database

Carry the talks, rota and recorders between the Cloud copy and the On-site copy.

Download the database

Replace this database with an uploaded one

What travels, and what does not {% filter markdown %} There are two copies of this app - the Cloud one and the On-site one (the badge in the navbar says which you are looking at). This is how the database moves between them. **Download** takes a consistent snapshot and hands you a `.sqlite` file. It is safe to do while the app is in use - it uses SQLite's own backup, not a plain file copy, so it cannot catch a half-finished write. What travels: the talks, the rota, recorders, editors, rota settings, and who has signed in. What does **not** travel: the audio. Recordings live in `/storage` and the app works out what has been recorded by looking for the files, so a database moved to a machine without them shows every talk as un-recorded. That is expected, not a fault. **Upload replaces everything.** There is no merge: the incoming talks, rota and recorders stand in for the ones here. The file is checked before anything is touched - it must be a real SQLite database, pass an integrity check, and not carry schema changes this version of the app is too old to understand - and a snapshot of the current database is saved into the instance directory first, so there is a way back. A restart is still needed afterwards to be certain every worker has let go of the old file. {% endfilter %}

Replace Talks File

The list of talks, as a UTF-8 CSV. Uploading one deletes all previous talk data.

Which columns the file needs {% filter markdown %} You'll probably get a list of talks in some sort of spreadsheet format from GBHQ. You'll normally need to do some prep work to get it ready to import: remove any talks that we don't want to record, rename the column headings to match the list below, and make sure that there is only one header line. Columns are matched by their heading; order doesn't matter. Extra columns and columns with typos in the heading are ignored. These seven columns are required: id Talk ID, e.g. "gb99-001" or just "1" title e.g. "My Great Talk" speaker e.g. "Dr Awesome" day e.g. "Friday" start_time e.g. "20:15", "8:15 PM" end_time e.g. "21:15" venue e.g. "A Field" These are optional, and default to empty or No if you leave them out: description e.g. "A wonderful not-to-be-missed talk about owls" is_priority is this a "must-record" talk? is_rotaed should the rota be built around this talk? is_cleared is it cleared for release? has_explicit_warning_sticker has_distressing_content_warning_sticker has_technical_issues_sticker has_copyright_removal_sticker recorder_name editor_name For the Yes/No columns you can use "Yes" or "No", "Y" or "N", "true" or "false", "1" or "0", or leave the cell blank for No. Times are read as a time of day and combined with the Day column, so the file still works next year. You can give a full "2026-08-29 20:15:00" timestamp if needed. Day names must be one of Friday, Saturday, Sunday or Monday (case-sensitive) {% endfilter %}
What replacing the file does {% filter markdown %} If anything in the file can't be read, nothing is imported at all: you'll get a message telling you which row and column is wrong, and the existing talks are left exactly as they were. So a failed import is safe. Replacing the Talks File deletes all previous data: assignments, rotas, etc. Files on disk aren't deleted, so if any talk IDs change, the files will be the wrong ones. If you replace the talks file when the festival has started, the rota will be meaningless, so make sure that you've got a copy saved! Any changes that affect the rota will need to be accounted for manually. It's probably best to talk to Rob before replacing the talks file during the festival. {% endfilter %}

Trusting the On-Site Certificate

Getting a front desk machine to stop warning about on-site.talks-processing.greenbelt.org.uk. You need administrator rights on the machine.

Windows 10 and 11 {% filter markdown %} The server talks on port 80 and 443. No redirect. This just saves us the HTTPS-by-default gotcha. The cert is signed by our own on-site CA. CA is valid until 2035. #### The quick way Open **PowerShell as Administrator** (right-click Start, "Terminal (Admin)" or "Windows PowerShell (Admin)"), and paste both lines: Invoke-WebRequest -Uri http://on-site.talks-processing.greenbelt.org.uk/gbtalks-ca.crt -OutFile $env:TEMP\gbtalks-ca.crt Import-Certificate -FilePath $env:TEMP\gbtalks-ca.crt -CertStoreLocation Cert:\LocalMachine\Root Close every browser window and reopen, then visit [https://on-site.talks-processing.greenbelt.org.uk/](https://on-site.talks-processing.greenbelt.org.uk/) - you should get a padlock and no warning. #### The clicking way If PowerShell is not an option: 1. Download [gbtalks-ca.crt](/gbtalks-ca.crt). Windows may warn about downloading a certificate file; that is expected, keep it. 2. Double-click the downloaded file, then **Install Certificate**. 3. Store Location: choose **Local Machine**, not Current User. Accept the UAC prompt. 4. Choose **Place all certificates in the following store** - *not* the automatic option it offers first - then **Browse** and pick **Trusted Root Certification Authorities**. 5. Next, Finish. Windows asks you to confirm installing a root certificate; the thumbprint it shows is ours. Yes. 6. Close every browser window and reopen. #### Gotchas These are the ones that actually catch people out: - **Local Machine, not Current User.** A Current User install only covers the account that did it, so the next volunteer to log in gets the warning back. The front desk machines are shared; always use Local Machine. - **Do not accept "Automatically select the certificate store."** It files the certificate under Personal, nothing changes, and the install looks like it succeeded. This is the single most common failure. - **Restart the browser properly.** Chrome and Edge keep background processes alive after the last window closes - check the system tray and quit from there, or just reboot. - **Chrome and Edge need doing once between them** - they share the Windows certificate store. Firefox has its own, but reads the Windows one by default. If Firefox alone still complains, set `security.enterprise_roots.enabled` to `true` in `about:config`. - **A rebuilt server means a new CA.** If the server is rebuilt from scratch mid-festival, every machine needs this doing again, and the old entry removed first. Routine playbook runs do *not* regenerate the CA, so a normal deploy is safe. To check whether a machine is already done, in any PowerShell: certutil -store Root | findstr /i "Greenbelt" Silence means it is not installed. {% endfilter %}
macOS {% filter markdown %} Same certificate, same reasons; only the trust store differs. You need an admin account on the Mac. #### The quick way In **Terminal**, two lines: curl -O http://on-site.talks-processing.greenbelt.org.uk/gbtalks-ca.crt sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain gbtalks-ca.crt It asks for your password, then possibly again in a dialogue. Quit and reopen the browser, then visit [https://on-site.talks-processing.greenbelt.org.uk/](https://on-site.talks-processing.greenbelt.org.uk/). #### The clicking way 1. Download [gbtalks-ca.crt](/gbtalks-ca.crt) and double-click it. Keychain Access opens. 2. If it asks which keychain, choose **System**, not Login. 3. Find **Greenbelt Recorded Talks On-Site CA** in the System keychain, double-click it, expand **Trust**, and set *When using this certificate* to **Always Trust**. Close the window and authenticate. 4. Quit and reopen the browser - Cmd-Q, not just closing the window. #### Gotchas - **Adding is not trusting.** Dropping the certificate into the keychain leaves it marked "not trusted"; step 3 is the part that matters, and the one people skip. The `security` command above does both at once. - **System, not Login.** A Login install only covers that user account. - Safari and Chrome use the system keychain. Firefox has its own - set `security.enterprise_roots.enabled` to `true` in `about:config`. - **A rebuilt server means a new CA**, here as on Windows. To check a machine: security find-certificate -c "Greenbelt Recorded Talks On-Site CA" /Library/Keychains/System.keychain An error means it is not installed. {% endfilter %}
