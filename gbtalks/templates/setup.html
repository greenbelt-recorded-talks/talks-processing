{% filter markdown %} ### Trusting the On-Site Certificate (Windows 10 and 11) The on-site server answers on both `http://` and `https://`, and there is **no redirect between them**. Plain HTTP keeps working exactly as it always has, so nothing below is urgent and nothing breaks if a machine skips it. What it buys you is the browser treating the site as secure: no "Not secure" warning next to the address bar, no nagging on the login form, and the secure-context-only browser features working. The certificate is signed by our own small certificate authority rather than a public one, because the on-site box is on a private festival network that Let's Encrypt cannot reach to verify. So each machine has to be told, once, that our CA is trustworthy. It is a two-minute job per machine and it survives reboots, updates and new festivals - the CA is good for ten years. You need local administrator rights on the machine. #### The quick way Open **PowerShell as Administrator** (right-click Start, "Terminal (Admin)" or "Windows PowerShell (Admin)"), and paste both lines: Invoke-WebRequest -Uri http://on-site.talks-processing.greenbelt.org.uk/gbtalks-ca.crt -OutFile $env:TEMP\gbtalks-ca.crt Import-Certificate -FilePath $env:TEMP\gbtalks-ca.crt -CertStoreLocation Cert:\LocalMachine\Root That is the whole job. Close every browser window and reopen, then visit [https://on-site.talks-processing.greenbelt.org.uk/](https://on-site.talks-processing.greenbelt.org.uk/) - you should get a padlock and no warning. #### The clicking way If PowerShell is not an option: 1. Download [gbtalks-ca.crt](/gbtalks-ca.crt). Windows may warn about downloading a certificate file; that is expected, keep it. 2. Double-click the downloaded file, then **Install Certificate**. 3. Store Location: choose **Local Machine**, not Current User. Accept the UAC prompt. 4. Choose **Place all certificates in the following store** - *not* the automatic option it offers first - then **Browse** and pick **Trusted Root Certification Authorities**. 5. Next, Finish. Windows asks you to confirm installing a root certificate; the thumbprint it shows is ours. Yes. 6. Close every browser window and reopen. #### Gotchas These are the ones that actually catch people out: - **Local Machine, not Current User.** A Current User install only covers the account that did it, so the next volunteer to log in gets the warning back. The front desk machines are shared; always use Local Machine. - **Do not accept "Automatically select the certificate store."** It files the certificate under Personal, nothing changes, and the install looks like it succeeded. This is the single most common failure. - **Restart the browser properly.** Chrome and Edge keep background processes alive after the last window closes - check the system tray and quit from there, or just reboot. - **Use the name, not the address.** The certificate covers `on-site.talks-processing.greenbelt.org.uk` and `gbtalks.local`, but deliberately no IP address, because the server's address is handed out by the venue's DHCP and changes. `https://10.something` will always warn; that is not a broken install. - **Chrome and Edge need doing once between them** - they share the Windows certificate store. Firefox has its own, but reads the Windows one by default. If Firefox alone still complains, set `security.enterprise_roots.enabled` to `true` in `about:config`. - **A rebuilt server means a new CA.** If the server is rebuilt from scratch mid-festival, every machine needs this doing again, and the old entry removed first. Routine playbook runs do *not* regenerate the CA, so a normal deploy is safe. To check whether a machine is already done, in any PowerShell: certutil -store Root | findstr /i "Greenbelt" Silence means it is not installed. {% endfilter %}

{% filter markdown %} ### Replace Talks File The Talks File is the list of talks. It must be a CSV file (with utf-8 encoding, otherwise accented characters won't work). You'll probably get a list of talks in some sort of spreadsheet format from GBHQ. You'll normally need to do some prep work to get it ready to import: remove any talks that we don't want to record, rename the column headings to match the list below, and make sure that there is only one header line. Columns are matched by their heading; order doesn't matter. Extra columns and columns with typos in the heading are ignored. These seven columns are required: id Talk ID, e.g. "gb99-001" or just "1" title e.g. "My Great Talk" speaker e.g. "Dr Awesome" day e.g. "Friday" start_time e.g. "20:15", "8:15 PM" end_time e.g. "21:15" venue e.g. "A Field" These are optional, and default to empty or No if you leave them out: description e.g. "A wonderful not-to-be-missed talk about owls" is_priority is this a "must-record" talk? is_rotaed should the rota be built around this talk? is_cleared is it cleared for release? has_explicit_warning_sticker has_distressing_content_warning_sticker has_technical_issues_sticker has_copyright_removal_sticker recorder_name editor_name For the Yes/No columns you can use "Yes" or "No", "Y" or "N", "true" or "false", "1" or "0", or leave the cell blank for No. Times are read as a time of day and combined with the Day column, so the file still works next year. You can give a full "2026-08-29 20:15:00" timestamp if needed. Day names must be one of Friday, Saturday, Sunday or Monday (case-sensitive) If anything in the file can't be read, nothing is imported at all: you'll get a message telling you which row and column is wrong, and the existing talks are left exactly as they were. So a failed import is safe. Replacing the Talks File deletes all previous data: assignments, rotas, etc. Files on disk aren't deleted, so if any talk IDs change, the files will be the wrong ones. If you replace the talks file when the festival has started, the rota will be meaningless, so make sure that you've got a copy saved! Any changes that affect the rota will need to be accounted for manually. It's probably best to talk to Rob before replacing the talks file during the festival. {% endfilter %}
